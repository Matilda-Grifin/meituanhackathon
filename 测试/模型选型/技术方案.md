## 3. 考卷与防刷题设计

| 集合 | 条数 | 用途 |
|------|------|------|
| 固定单轮 50 | 50 | 六模型主对比（选型主成绩） |
| 固定多轮 50 | 50 | 多轮记忆 / 追问 / 改方案 |
| **隐藏卷 15** | 15 | 从 500 条大库中抽出、**不在**固定 50 内；全量结束后只对入围 1～2 个模型补跑 |
| 日常冒烟 ~26 | dev | 改人设时快速回归，**不作为选型主成绩** |

多轮：**用户可见**的对话在考卷里；**判分规则**在独立裁判文件里，不进入模型输入（自检会检查是否泄露）。

## 4. 指标口径（答辩只说这些也够）

### 单轮 / 多轮共用

| 名称 | 含义 | 怎么看 |
|------|------|--------|
| **任务成功率（Pass@1）** | 这道题是否完整做对 | **北极星**，优先比这个 |
| **平均分（Avg@1）** | 六维细则加权，0～100 | 和成功率一起看，防止「做对但质量差」 |
| **分难度** | 简单 15 / 中等 25 / 难题 10 | 防止模型只会简单题 |

### 多轮额外五项（脚本自动判）

| 指标 | 通过线建议 |
|------|------------|
| 上下文记忆 | ≥ 85% |
| 追问是否有效 | ≥ 80% |
| 改约束后能否重规划 | ≥ 75% |
| 工具顺序是否合规 | ≥ 90% |
| 最终是否可执行 | ≥ 70% |

### 决策矩阵新增（已写入汇总逻辑）

- 每题平均 Token（有上报时统计）
- 每题平均工具调用次数
- 平均首响耗时（毫秒，有则统计）

## 5. 稳定性抽查（可选，全量后）

固定 **10 条难题**（与正式 50 条中的难题一致），对**入围模型**各跑 **3 遍**，回答「是不是偶尔蒙对」：

```powershell
# 示例：豆包第 1 遍（only 列表见 模型选型/stability_subset.json）
python 模型选型/run_model_benchmark.py --models doubao --datasets singleturn --only 22,426,443,444,445,448,454,457,494,499 --run-id 20260602-stab-doubao-r1 --skip-self-check
# r2、r3 同理改 run-id

python 模型选型/aggregate_stability.py --model doubao --runs 20260602-stab-doubao-r1,20260602-stab-doubao-r2,20260602-stab-doubao-r3
```

输出解读：

- **至少成功一次的比例**：探索能力强，但可能不稳定  
- **三次全中的比例**：真正稳定，适合上线主模型

## 9. 答辩一页纸（怎么讲）

1. **我们测的不是做题能力，是 Agent 能不能帮用户完成本地出行规划**（任务成功率为主）。  
2. **考卷固定 50+50**，难度按比例抽样，避免只刷日常练习题。  
3. **六模型在同一网关、同一人设、同一温度下对比**，结果可复现。  
4. **报告里有分难度表、失败类型饼图、成本柱图**，对标 VitaBench 论文图表，但场景是本赛题。  
5. **选型结论**：主看任务成功率 + 难题表现 + 多轮五项 + 单次成本；隐藏卷 15 条验证未刷题。  
6. **为何暂不搞多模型路由**：现阶段人设仍在迭代，单主模型归因简单；费用优化留到 P3。

更口语版见 HTML **§14 答辩汇报（易懂版）**。
