# 出行意图与反问（槽位采集）

## 何时使用

仅 **大阶段一 · 用户要完整行程且槽位未齐** 时启用（见 `SOUL.md` 对话阶段路由与 **travel-intake 执行摘要**）。  
规则摘要已在 `SOUL.md` bootstrap 中；**A 阶段勿再 `read` 本文件**。  
用户刚提出游玩/出行目标，或关键槽位任一不明确时 必须优先 启用；未完成本 skill 前禁止调用 `lifecare__lifecare_search_places` 与 `lifecare__lifecare_plan_route`。

**不要** 在以下情况再用本 skill：纯天气/闲聊；**本会话已给过完整方案** 后的跟进（改午饭、问细节、改室内、补「想看博物馆/改面食」等 → **SOUL 大阶段二模式②**，调工具改版，**禁止**再出选择题）；**同一趟行程** 已出过一轮选择题（除非 **整趟换纲**：换城市、周边↔跨城、半日↔多日游）。

**007 硬反例**：方案已出，用户说「想看博物馆、逛公园、吃面食」→ **不是** intake，是 `local-itinerary-planner` 模式②。

**禁止重复问卷**：若上一条 assistant 已输出完整 2～3 道选择题，紧随其后的用户消息 **仅为** `[位置上下文]`（浏览器定位注入）时，**不得**再输出第二遍相同/相近问卷；应等待 `选择题答案：…` 或「全部用默认」。

## 口语跳过问卷（WebChat · intake_skipped_via_freetext）

用户 **不点选**、在对话框用可见句子回复已展示的选择题 → **跳过 intake**，直接进入 B 阶段。

| 规则 | 说明 |
|------|------|
| 不再出第二套题 | 本趟行程已 `intake_consumed`；仅 **整趟换纲** 可重新问卷 |
| 槽位来源 | 用户首句 + 口语回复 + `[位置上下文]`；**禁止**从 MEMORY 猜人数 |
| 默认人数 | 未提及 → **2 成人**，B 阶段首句须声明 |
| 低置信度 | **不追问**；采用合理默认并在首句写「未说明，按 X 假设」 |
| 首句模板 | `收到，不再重复问卷。按您的描述：{slots}；{时间假设及理由}。正在查天气并搜点…` |
| 时间规则 | `T_end_soft=22:00`，`prep_buffer=30min`，`play_duration` 默认 4h（半天） |

**出发时间判定**（通用，不写 case 专项阈值）：

```text
remaining_playable = T_end_soft - (T_now + prep_buffer)

若 play_duration > remaining_playable 且用户未坚持「今晚/现在就要出去」：
  → plan_day = 明天，depart_window ≈ 09:00，首句说明「今晚剩余时间不够 {play_duration}」

若用户坚持今晚出去但 remaining 不够：
  → 压缩今晚：1～2 个近点 + 一顿，首句说明「只能安排约 X 小时轻量动线」

否则：
  → plan_day = 今天，depart_window 按 T_now
```

## 第一步：拆解用户原话（必做，写在内心 checklist，复述里体现）

出任何选择题之前，先从用户**可见首句**（不含 `[位置上下文]`）提取已给出的槽位；**已明确的槽位禁止再问**，也禁止换说法问第二遍。

| 用户关键词/句式 | 视为已填槽位 | 禁止再问的题 |
|-----------------|-------------|-------------|
| 今晚 / 晚上 / 夜间 / 傍晚 / 夜逛 | 出行时段 = 今晚晚间 | 「哪天玩」「上午/下午」；勿用「半日/一日/两日」选项冒充时段题 |
| 明天 / 后天 / 周六 / 周末 / 上午 / 下午 | `depart_window` 或日期时段 | 出发窗口题（同维度） |
| 现在 / 马上 / 这就出发 | `depart_window=now` | 出发窗口题 |
| 附近 / 周边 / 逛逛 / 散步 / 不出城 | 场景 B + 范围倾向本地 | 「出行范围半径」「去哪个城市玩」 |
| 城里 / 市内 / 本地 + 玩/逛 | 场景 B（当前城市本地） | 「在哪个区域游玩」；勿误判场景 A |
| 去××市 / 几日游 / 出差×× | 场景 A + 目的地 | 重复问目的地城市 |
| 1人 / 独自 / 2人 / 双人 / 3-4人 / 一家 / N 人 | 人数 | 任何「总人数」「同行人数」类题（**一轮 intake 最多 1 道人数题**） |
| 自驾 / 地铁 / 打车 / 步行 | 本地或到达交通 | 同类型交通题 |
| 半天 / 一天 / 几小时 / 2-3小时 | `play_duration` | 「玩多久」题 |
| 10:19 到 / 21:35 回 / ××站到 / 发车 | 场景 A：`arrival_hub` / `departure_time` 等 | 大交通或站点题 |
| 古镇 / 博物馆 / 乐园 / 爬山 / 海边 | 可推断 `place_type` | 地点类型题（若很明确） |
| ××区 / 从×× / 在××一带 | `district` 或地标出发 | 「哪个区出发」题 |
| 六点前回 / 几点前回家 | 软约束 `T_end`（**不占 intake 题**） | **禁止**单独问「回程」 |

**去重铁律：**

1. 本轮 2～3 题里，**每个槽位维度最多出现 1 次**（人数、时段、区、交通、时长、到达方式、地点类型、出发窗口、玩多久等不得重复）。
2. 复述已写明的信息，选择题只问**仍空缺**的维度。
3. 选项语义须与题干一致。

## 先分场景（必做，写在复述里）

| 场景 | 识别信号（满足其一即可倾向） | 规划含义 |
|------|------------------------------|----------|
| A. 城市出行 | 去××市/异地/旅行/几日游/出差住店/「去北京玩」 | 以目的地城市为中心；要问清怎么到这座城市 |
| B. 周边游玩 | 周边/附近/郊野/不出城/半日溜娃/「在附近逛逛」/**城里玩/市内玩一天**/未点名异地城市 | 以用户当前位置为圆心；位置优先用网页定位 |

禁止混淆：用户说「晚上在附近逛逛」= 场景 B + 时段已有，不得当成去异地城市三日游。  
禁止混淆：用户说「想在城里玩一天」= **场景 B 本地一日**（圆心=定位区），**不是**场景 A 跨城出行；**禁止**问「在哪个区域游玩」——高置信定位已有区时直接采用，只问仍缺槽位。

## 场景 B：周边游玩（本地半日/一日）

### 位置与城市（与 `[位置上下文]` 配合）

1. **城市**：若 `[位置上下文]` 已有 `city`，**直接采用**，不要再问「在哪个城市」。
2. **仅当 city 为空** 时，才用一题确认城市（A/B/C 具体城市名 + **D. 其他**）。
3. **区/地标**（与 city 对齐，按置信度分级）：
   - **直接采用、不问区**：用户原话已含区名/地标；或 `[位置上下文]` 写明「区=×× 已由定位填写…勿再问哪个区」（浏览器定位 + regeo 区县级 + 精度 ≤500m）。
   - **须问一题**：仅 IP 定位、无 `district`、或定位置信度低时。题干用「从哪个区或地标出发」，A 可为「××区（当前定位）」；禁止「出行范围/公里圈」题。
   - 复述高置信区时写「从××区出发（定位）」；默认行含该区；用户要改区走口语或方案后追问，**不占 intake 题**。
4. **`return_to`（回程）**：**不问**。默认 = 定位区/地标（与出发地相同）；摘要须写 `return_to=…`。用户原话写了别的回家点则写入摘要。

### 场景 B 必填槽位（缺则进 2～3 题，从空缺里选）

| 槽位 | 何时问 | 说明 |
|------|--------|------|
| `place_type` | 原话无法推断类型 | 见下「地点类型题」A–F |
| `depart_window` | 原话无 现在/明天/周末/今晚 等 | 见「出发窗口题」 |
| `play_duration` | 原话无 半天/一天/几小时 等 | 见「玩多久题」 |
| 人数 | 原话无人数 | 全轮最多 1 道人数题 |
| 本地交通 | 未提及且需要写地铁方案时 | 自驾/地铁+公交/打车/步行 |

**禁止**：单独问「回程几点到家」；禁止问高铁到站/机场/离站。

#### 地点类型题（占 1 题，可含 F 选项）

```markdown
N. 更想逛哪一类地方？（周边）
**A.** 自然景观类（山水、森林郊野、滨海、地貌花海等）
**B.** 人文历史类（古镇古迹、园林寺庙、红色文旅等）
**C.** 城市休闲类（商圈地标、城市公园、博物馆展馆等）
**D.** 主题游乐类（乐园、影视民俗、房车营地等）
**E.** 户外探险类（徒步、露营、漂流、攀岩；含农家乐、采摘、乡村民宿、农耕体验等）
**F.** 以上都行
```

- **D = 主题游乐**，勿把 D 写成「其他」。无 G 选项。  
- 选 **F** → 摘要 `place_type=any`。

#### 出发窗口题

```markdown
N. 打算什么时候出发？
**A.** 现在（马上）
**B.** 明天
**C.** 本周末
**D.** 其他（选填，如：周六上午 / 后天下午）
```

- 用户选 **A.现在** 时，须读 `[位置上下文]` 里的 **当前当地时间** 作为 `T_now`。

#### 玩多久题

```markdown
N. 大概想玩多久？
**A.** 2–3 小时
**B.** 半天（约 4–6 小时）
**C.** 一天（约 9:00–23:00）
**D.** 其他（选填）
```

### 场景 B 结构化摘要（槽位齐后）

首行 `场景：B`，并尽量包含：

`place_type`、`depart_window`、`play_duration`、`return_to`（定位默认）、若 `depart_window=now` 则 `T_now` 与 `可玩截止：当日 23:00`（用户口头「六点前回」则改 `T_end` 为 18:00 等，仍回 `return_to`）。

## 场景 A：城市出行（短途/长途到某城）

必填（缺则进 2～3 题，且遵守「已填不问、不重复」）：

- 目的地城市（原话已点名则不问）。
- 出行日期/时段（原话已含则不问）。
- 人数（原话已含则不问；全轮只 1 道人数题）。
- **大交通**（未提及才问，占 1 题）：

```markdown
N. 你打算怎么去{目的地}？（主段大交通）
**A.** 高铁/动车{{followUp:到达/离开站点（选填）及时间}}
**B.** 自驾（从当前城市出发）
**C.** 飞机{{followUp:到达/离开机场（选填）及时间}}
**D.** 其他（请说明）
```

- 用户原话已含到站/发车时刻 → 写入 `arrival_hub`、`departure_hub`、`arrival_time`、`departure_time`，**禁止**再问大交通。
- 用户提交 `第N题选A：虹桥 10:00 到，21:00 回` 或带 `子N：` 子字段 → 解析进摘要。
- 游玩时长、口味/忌口：按缺口选问。

## 步骤（两场景通用）

1. 一句复述：场景 A|B + **从原话与定位已知的槽位** + 仍缺什么。  
2. 只输出 **2～3** 道选择题；场景 B 地点类型题可用 **A–F**；其余题惯例 **A/B/C/D**（D=其他）。题号连续，**不重复维度**。  
3. 附「或直接回复：全部用默认」+ 默认假设（场景 B 默认含「从定位区出发」、`return_to` 同定位区）。  
4. 槽位齐或默认后，输出结构化摘要（首行 `场景：A|B` + 键值），再进入 `local-itinerary-planner`。

## WebChat 问卷排版（强制 · 与前端解析器一致）

出选择题时 **必须** 使用下列格式，**不得**自行发挥 Markdown/emoji 题号：

```
1. 题干（一句话）
A. 选项
B. 选项
C. 选项
D. 其他（请说明）

2. 下一题题干
A. …
```

- 题号：仅 `1.` `2.` `3.`（数字 + 英文句点 + 空格）
- 选项：仅 `A.`～`F.` 每行一个
- 题间：空一行；**禁止** `---`、`**加粗题号**`、`1️⃣`、`第1题`
- 用户通过 Web 提交时句式为 `选择题答案：第1题选A；第2题选B`（由前端生成，你只需按上格式出题）

## 首 Token SLA

- 本 skill：不要先调 MCP；先文字反问。  
- 用户已给全槽位：一句确认 + 结构化摘要后进入规划。

## 反例（禁止）

用户：「我晚上想在附近逛逛」，定位：杭州市西湖区（浏览器定位，精度约 69 米）。

- 禁止：问回程题、问「半日/一日」时长题（晚间已隐含短游）、重复问人数、**高置信定位已有区时再问「哪个区」**。  
- 合理：复述「场景 B · 今晚 · 从西湖区出发（定位）」；缺则问 **地点类型** 或 **交通** 之一 + 人数（若未知）。

用户：「想在城里玩一天，要安静、适合出片」，定位：上海市闵行区。

- 禁止：当成场景 A 跨城出行；禁止问「在哪个区域游玩」及把闵行放进选项 A。  
- 合理：场景 B · 闵行出发 · 一天 · 安静出片倾向；缺则问 **人数**、**出发时间** 或 **地点类型**（2 题）。

## 边界

- 不收集身份证号、手机号。  
- 大交通不做真实订票。
