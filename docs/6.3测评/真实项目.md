## 3. 模拟测评会不会影响线上 Agent？（结论 + 具体落点）

**结论：会，但只影响「和 Agent 共用同一套 OpenClaw 工作区 / 网关配置」的部分；测评专用的调度器、用户模拟器、裁判不会跑在线上。**

线上页面 `https://121.41.81.58:8080/` 与 6.3 批量测评用的是**同一台 ECS、同一个 OpenClaw Gateway（18789）和同一份 `workspace/`**（`SOUL.md`、skills、MCP）。部署脚本 `gateway-chat-ui/scripts/ecs_apply_lifecare_openclaw.py` 会把仓库里的 `meituan-lifecare-agent/workspace/*` 同步到 `~/.openclaw/workspace/`。因此下面几项**测评改过，线上也会跟着变**：

| 影响项 | 模拟测评里做了什么 | 线上表现 |
|--------|-------------------|----------|
| **人设与对话规则** | `workspace/SOUL.md`（阶段 A/B、选择题、长方案结构） | 网页里 Agent 同样按 SOUL 说话；**含「6.3 测评结束标记 ###STOP###」一节时，线上模型也可能在合适时输出 STOP**——真实用户不需要，建议线上专用 SOUL 去掉该节或改说明 |
| **Skills** | `travel-intake`、`local-itinerary-planner`、`mock-user-prefs-reviews` 等 | **线上保留同一套**（含行程规划 + 用户语料 skill）；与测评一致 |
| **工具链** | 天气 / 高德 POI / 路线 MCP | 线上相同；**用户评价语料**在 `search_places` 的 reputation 字段 + `mock-user-prefs-reviews` skill 里，线上有 |
| **网关主模型** | 批量测评用 `ecs_switch_model.py qwen`（DashScope qwen3.6-plus，thinking=medium） | 需单独执行切换；**已可按下面命令把线上也切成 Qwen**（与测评对齐） |
| **首轮注入的「环境块」** | 测评在每题**第一轮**注入 `[仿真环境-只读]`：虚构住址、历史订单摘要、口味偏好等（`vitabench_eval/agent_bridge.py`） | 网页**不注入**这套 fiction；改为浏览器定位/IP 注入 `[位置上下文]`（城市、区、坐标、场景 A/B 提示，`gateway-chat-ui/src/location.ts`），**没有**虚构居住地址与历史订单 |
| **用户从哪来** | 用户模拟 LLM（OpenRouter + 代理）按 hidden instructions 多轮发言 | 真实用户在网页输入 |
| **结束方式** | 用户模拟器发 `###STOP###` → 调度器结束 → 裁判打分 | 用户自行停止聊天；**无 STOP、无裁判** |
| **测评专用环境变量** | `V63_EVAL_THINKING`、`V63_AGENT_LOCAL` 等仅 `run_benchmark.py` / batch 使用 | **不影响**网页 |
| **OpenRouter / 裁判 / 用户模拟** | 走 IPRoyal + OpenRouter | **线上 Agent 不走**；仅测评 batch 用 |

**不会**因为跑过 50 题 batch 而在线上自动多出一个调度器或裁判；**会**因为共用 SOUL/workspace/网关模型，而出现「测评为 STOP、长方案、选择题」等行为在线上同样生效。

### 线上缺什么、测评多什么（与你上面第 1、2 点对照）

- 测评 Task JSON 里的 **虚构住址、历史订单、完整 user_historical_behaviors** → 仅测评注入；线上只有定位/时间/天气/高德/餐厅 reputation 工具数据。
- 测评 **50 条固定场景 + rubric** → 线上无；用户自由提问。
- 测评 **9 条助手异常**（3 超时 + 6 桥接空消息）是 OpenClaw CLI 批量调用问题，网页 WebSocket 路径可能表现不同，但**共用网关**，模型/超时时限仍相关。
