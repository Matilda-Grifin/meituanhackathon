# 6.3 人工评测 · 10 Tasks（浏览器定位版）

> **适用**：测试者浏览器已授权定位（页顶显示「当前位置推测：…」），如杭州紫金港。  
> **与原考卷区别**：原 [`人工评测_10任务集.md`](./人工评测_10任务集.md) 绑定了北京/上海/成都等虚构住址；**本版不要求 Agent 去那些城市**。  
> **唯一地理真源**：WebChat 注入的 `[位置上下文]` + 页顶定位 → Agent 应以**用户当前城市/区县**搜 POI、查天气、规划动线。

---

## 通用原则（人工 + 自动 rubric 均按此）

| 项 | 浏览器定位版 |
|----|----------------|
| **出发地** | 用户当前定位（如西湖区三墩镇），不是考卷里的「望京 SOHO」 |
| **天气** | 查**定位所在城市**当次出行时段天气，不要求「北京 2026-06-14」 |
| **POI** | 高德返回的**本地真实 POI**；杭州测不应硬凑「外滩/中央大街/民族村」等异地地标 |
| **意图** | 保留：亲子/科技馆、小吃重辣、赶高铁、无障碍等**玩法与约束** |
| **首句话术** | **不要**在首句写「去上海玩」「春熙路附近」等异地；用「附近/城里/跨区」 |

自动打分脚本已改为读 [`测试/manual_eval/intent_keywords.json`](../../meituan-lifecare-agent/测试/manual_eval/intent_keywords.json)，按**意图关键词**（科技馆、展览、高铁…）匹配方案，不再要求方案出现原考卷城市名。

## 人工 rubric 对照（与原表差异）

原表 R1 写「查询**北京**天气」→ 本版改为：**是否查了定位城市天气并在方案中体现**。  
原表 R5 写「从**望京**出发」→ 本版：**是否从 `[位置上下文]` 区县/地标周边出发**。  
原表 R7 写「**外滩/中央大街**」→ 本版：**是否满足该 Task 玩法意图**（见 intent_keywords）。

其余 R2 POI 工具、R3 锚点数量、R4 预算/忌口、R6 分时段、R8 未完成即结束等**不变**。
